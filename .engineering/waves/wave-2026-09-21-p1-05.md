## The shape changed before dispatch, and this is the deviation to read first

The plan says two units in parallel. It is **three units, the first alone and the other two in
parallel after it**, because a prerequisite neither story declares turned up on the pre-dispatch
read.

`ekr_ontology::Value` has a `Float(f64)` variant. `crates/ekr-core/src/canonical.rs` rule 4 admits
no float, so `Value` has no `Canonical` implementation, so `ekr_graph::Assertion` has none —
`Object::Value(Value)` at `assertion.rs:37`, and both property maps. Wave p1-04's implementor
recorded this and said the kernel's knowledge-root hashing would meet it in a later wave. It is this
wave, and **both units meet it at once**:

- `story:eventlog-store` must fold to a head `Root` hash, and `Root.knowledge_root` and
  `Root.evidence_root` (`root.rs:57-59`) are content addresses of graph and evidence state.
- `story:transaction-and-validators` ships a case that a valid transaction produces the same
  `validation_hash` twice, over operations that carry values.

`aep plan artifact waves` reported 0 collisions, and it was right about the declared scopes and
wrong about the work: neither story declares `crates/ekr-graph/src/`, and both units would have
reached into it for the same change. **This is the collision the verb cannot see** — the one the
plan itself flagged as `crates/ekr-graph/src/*`, *highest risk*.

Settled as `architecture-decision-record:0005-float-is-not-canonical`, accepted, and implemented as
unit 0 before the other two fork.

## The second thing the pre-dispatch read found, and it is bigger

**`eventlog-core`'s `EventStore` trait is async and this workspace has no runtime.** Every method
returns a `BoxFuture` (`eventlog-core/src/lib.rs:43`, `:668-684`); `eventlog-sqlite` and
`eventlog-file` both depend on `tokio` with `rt`, and the eventlog repository's own suites drive
them with `#[tokio::test]`. `[workspace.dependencies]` declares no `tokio`, no `futures`, no
`pollster`, no `smol`.

`story:eventlog-store`'s Notes said "this story adds no dependency and does not touch `Cargo.lock`,
so it can run beside `story:transaction-and-validators`" — and that sentence was the **whole**
parallel-safety argument for this wave. It is false. The conclusion survives, because
`story:transaction-and-validators` genuinely touches none of the three manifest files, but it now
rests on a reading of the dependency rather than on a story's own wrong claim.

Settled as `architecture-decision-record:0006-ekr-store-bridges-the-async-port`, accepted: `tokio`
joins the workspace with the `rt` feature, `ekr-store` owns a current-thread runtime, and its
`RevisionLog` is synchronous so `ekr-kernel`, the CLI and everything above stay synchronous. The
cost is recorded rather than hidden — `block_on` panics when called from inside a runtime, and
`task:ekr-store-block-on-cannot-nest` says what closes it.

`Cargo.toml`, `Cargo.lock` and `crates/ekr-store/Cargo.toml` are in unit 1's scope for that change
and no other. They are the one exception to the coordinator owning shared surfaces this wave, and
they are an exception because only one unit touches them.

## The decision, in one paragraph

**A `Float` is not admissible in canonical state.** Rule 4 already says a quantity that must be
hashed is carried as an integer or a decimal string, and that this is what `ekr.ontology.ValueKind`
distinguishes `Float` from `Decimal` for; ADR 0005 makes that enforceable rather than advisory. A
newtype in `ekr-graph` is inhabited only by an admissible value, refuses a `Float` at any depth, and
has a total `Canonical` implementation. `Assertion` then has one, and `knowledge_root` becomes
computable. `Float` stays legal in `ekr_ontology::Value` and in the transient graph, which is not
content-addressed. The kernel's type validator refuses an inadmissible value, which is unit 2's half
and is in its story's scope.

Unrepresentable rather than refused, which is the shape this repository has taken twice: `AGENTS.md`
invariant 2, and wave p1-04's `TransactionTime`. The alternative, a fallible `Assertion::content_hash`
whose error validation makes unreachable, is a claim nobody can check.

## What adversary pass 1 on unit 0 changed, before units 1 and 2 forked

Holding the wave at unit 0 paid for itself. The blocker it found would have cost three rebases had
the other two forked first.

**ADR 0005 contradicted itself and the implementation took the wrong half.** The record says a
`Float` stays legal in the transient graph. `TransientGraph` is composed of the same `Node`, `Edge`
and `Assertion` canonical state holds (`transient.rs:124-128`), so moving those three to the
admissible newtype made a float unholdable everywhere, incubation forest included.

The ADR is amended and the fix is the more expensive of the adversary's two options: **`Node`, `Edge`
and `Assertion` are generic over the value they carry**, defaulting to the admissible newtype, with
`Canonical` implemented only where that parameter is itself `Canonical`. `CanonicalGraph` holds the
default; `TransientGraph` holds the same types over `ekr_ontology::Value`.

The reason for taking the expensive option: **the address then exists exactly where canonical state
does.** "Only canonical state can be content-addressed" stops being a convention and becomes a
property of the type system, which is the shape `AGENTS.md` invariant 2 already asks for on the
reference direction. The cheap option — deleting the ADR sentence — would have made the membrane
weaker rather than described it.

The second blocker is the wave's recurring lesson at a new address: eight payload lines can be
deleted from `ValidationState::encode` with all 216 cases still green, because the mutation table's
row for that field changes the *variant* and never a payload within one variant. Two more fields
have the same hole. A mutation table is a claim about a class, and a row that varies one field does
not test the others.

`task:typed-value-canonical-field-is-undecided` carries the fourth, which is not merely a wrong
sentence: nobody has decided what that field is for.

## What unit 0 cost, and what it bought

Three rounds, 970k sub-agent tokens, two adversary passes, 199 → 231 cases. It was not in the
approved plan at all.

It bought the thing the plan's two units both needed and neither declared, and it bought one more:
`Canonical` is implemented only where the value parameter is itself `Canonical`, so **the address
exists exactly where canonical state does**. `AGENTS.md` invariant 2 asked for that shape on the

that variant appears twice with different payloads. The fixtures now assert that rule off the
encoded bytes rather than remembering it.

## Both units found a defect in themselves before any adversary read them

This is new. In four waves before this one, every vacuity and every real defect in an implementor's
work was found by an adversary pass.

**Unit 1's first stub measurement killed zero cases, and it led its report with that.** Its fixture
computed the root a commit publishes with the same function the fold checks it against, so a stub
agreed with itself and the acceptance held just as well for a store that lost every node. Three
cases pinning the sub-roots as functions of state fixed it; the same stub then killed one.

**Unit 2's property test found a hole in its own type validator.** The validator skipped a whole
operation when it could not name the node's type, so a float under an unresolvable node reached no
refusal of its own — while that file's doc claimed admissibility "is asked of every value".
Admissibility is now a separate first pass over every value in every operation, and the regression
seed is checked in.

Both briefs carried the same four warnings, drawn from what the previous three waves cost, and
`prove the suite is not vacuous before you report` is the one that paid.
