# Seed evidence scope

Owners: kernel seed implementor; coordinator for the bootstrap contract and later-phase tracking.

Read-only static assessment; no builds or probes were run for this report.

P1 should retain the actual content of each admitted seed HumanStatement and verify its content hash. Retaining only an Evidence record containing an arbitrary hash and a source label does not establish that the supporting statement is retained. P1 need not implement observation ingestion or derived graph evidence to close this boundary: the smallest defensible seed contract admits HumanStatement evidence and explicitly refuses other source kinds at bootstrap until their dependencies can be resolved.

The normative basis is narrower than “archive every external source forever.” Design §6.1 requires retained admissible evidence and §6.2 requires every committed reference to resolve (`docs/epistemic-knowledge-runtime-design.md:330`, `:352`). Section 16 models Evidence as metadata and qualifies reproduction by policy (`:848`, `:890`); it does not prescribe one universal payload layout. Section 21 nevertheless requires referential completeness and provenance compliance (`:1061`), and §37 retains provenance while needed to verify, audit or reproduce assertions (`:1759`). The seed's existing story specifically chooses HumanStatement for initial assertions (`.engineering/planning/story/seed-and-explain.md:58`). Amendment 81's statement contains both a speaker identity and actual statement content (`docs/epistemic-knowledge-runtime-design.md:3191`). That is sufficient reason to retain the seed statement, without pulling P2's observation subsystem into P1.

Current implementation establishes less. Evidence.content_hash is documented as the address of what was read, distinct from the address of the Evidence record (`crates/ekr-graph/src/evidence.rs:238`, `:253`). HumanStatement currently stores only an optional identity string, GraphAssertion only an AssertionId, and Observation only an ObservationId (`:58`). Reference validation resolves an assertion's EvidenceId against graph.evidence keys (`crates/ekr-kernel/src/validate/reference.rs:120`, `:195`); provenance validation requires a nonempty evidence list (`crates/ekr-kernel/src/validate/provenance.rs:92`). Neither resolves source targets or content bytes. CanonicalGraph has no observation collection (`crates/ekr-graph/src/canonical.rs:321`). An EvidenceId lookup therefore cannot establish either payload retention or an Observation target's existence.

Recommended bounded contract:

1. Add a retained content map to the versioned seed envelope, keyed by content hash, with the exact statement bytes as values. For every Evidence record admitted into seed canonical state, require HumanStatement source, a resolvable payload, and `ContentHash::of_bytes(payload) == evidence.content_hash` (`crates/ekr-core/src/hash.rs:66`). Check every retained Evidence record, including initially uncited ones: a later valid transaction may cite any retained EvidenceId. Continue enforcing map/id agreement and nonempty, resolvable assertion evidence lists.
2. Include those bytes in the seed envelope published atomically with Seeded. Retaining them inside a Canonical seed object is sufficient for this unit; separate Provenance objects are optional and must participate in the same atomic publication if used. Replay must recover the bytes and repeat the hash checks. Provide a deterministic lookup from the seed's content map so later explain work can reach the statement. No Graph Evidence schema change or new observation store is necessary.
3. Persist execution-supplied bootstrap attribution binding the seed admission to its operator and validators. Do not treat the payload's free-text HumanStatement identity as authenticated authority; it is source metadata. This unit does not implement Amendment 81's interactive attention-answer protocol or general authentication policy.
4. Refuse GraphAssertion and Observation source variants by named unsupported-source refusal. They cannot become valid merely because the containing EvidenceId exists. Supporting them later requires resolving their actual targets within the permitted retained domain and establishing the content binding; GraphAssertion chains must ultimately have independent supporting evidence. Do not invent a hash translation or let self-reference stand in for that support. Refuse Url, Document and DatabaseRecord bootstrap evidence under the same explicit HumanStatement-only contract; those remain source kinds for later ingestion, rather than silently accepted metadata today.

Acceptance in `crates/ekr-kernel/tests/seed.rs`, through both real backends: a HumanStatement-backed seed with retained matching bytes admits and reopens; removing payload bytes, changing bytes without changing the cited hash, or citing a missing EvidenceId refuses before any publication; GraphAssertion/Observation sources refuse even when the EvidenceId exists; an otherwise-valid seed with no assertions or evidence remains admissible. Tampered retained content fails reopen. An initially uncited invalid Evidence record also refuses. Existing legacy seeds lacking verifiable content remain preserved with the migration refusal; no synthetic statements or lineage reset.

This payload map and the bootstrap source restriction are implementation recommendations, not a previously specified serialization format. Record them in the owning seed story before dispatch. Source credibility thresholds, source-specific admissibility, configurable trust profiles and confidence policy remain later work (`crates/ekr-kernel/src/validate/provenance.rs:23`; `docs/roadmap.md:204`). Observation capture and blob retention belong to P2 (`docs/roadmap.md:148`; design §86 at `docs/epistemic-knowledge-runtime-design.md:3391`). Those deferrals do not defer checking the existence of a canonical dependency admitted now.
