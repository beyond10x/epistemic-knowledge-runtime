# Read-only preparation — story:kernel-validated-seed

Prepared against the integration worktree on 2026-09-22. No repository edits, builds, AEP writes or commits were performed for this preparation. The story is draft revision 3; its dependencies are the membrane repair and eventlog-store. The membrane implementation has landed. This report is the only preparation output written outside the repository.

## Findings that must shape the implementation

1. `EventlogStore::fold_from` in `crates/ekr-store/src/eventlog.rs` currently fetches the seed object's bytes, calls `GraphDocument::from_bytes(...).into_canonical(self.ontology.clone())`, then constructs `Fold::seeded`. That production crossing must be removed. Adding validation only to an initial `Commit::seed` would leave forged or old input accepted on reopen.
2. `CommitAuthority` currently attests only ordinary transaction validation triples. Kernel `Validations` stores those triples in process-local memory. Seed admission must be an additional stateless authority operation which parses and revalidates retained seed input every time. A second hash allow-list would reproduce the durability defect.
3. `RevisionLog::append` always uses `Expected::Any`; prechecking head is insufficient against concurrent initializers. The initialization append must use `Expected::NoStream`. Map the provider's typed `EventLogError::Conflict` before the existing conversion flattens all provider failures to `StoreError::Backend(String)`.
4. `ObjectStore::get` returns bytes from the object record without recomputing their content hash or checking record metadata against the requested stream address. Seed replay must verify `ContentHash::of_bytes(bytes) == Seeded.seed_hash` before admission. Otherwise tampered but still valid seed data can change the reconstructed graph under the same event address.
5. A full ontology already lives in proposed `SeedDocument.ontology`; persist that document, not just the graph plus schema version id. `Ontology` implements structural `PartialEq/Eq`, so loading the persisted document and comparing the complete ontology to the constructor's compatibility ontology is possible without adding any ontology API. A round-trip export method is needed only if the chosen public constructor also promises to derive a seed document from an arbitrary existing `Ontology` or `CanonicalGraph`.
6. Existing store fixtures are intentionally not valid canonical seeds: their ontology has no types, graph entities use fresh undeclared type/property IDs, node and edge types reuse one id, and assertions are Accepted with no validators. They cannot be routed through the real kernel by merely updating a method call.
7. Kernel `commit_path.rs` creates its seed through `Commit::store`, and uses the same accessor for readback and forged-event tests. Readback becomes explicit `head`, `snapshot`/`fold`, and `replay` methods. Forged-event tests must open a separate test-only raw provider handle. No production raw writer accessor should survive.
8. Seed initialization and ordinary transaction commit are distinct bootstrap cases. `ValidatedTransaction` requires a previous `RevisionNumber`, and ordinary `Pipeline::validate` refuses an empty operation list. Manufacturing revision zero as a previous committed revision would contradict the story's explicit no-prior-revision rule. A private kernel bootstrap capability, constructed only by seed validation and consumed by the same owned store boundary, is the clean implementation; clarify the literal invariant wording if it currently implies seed initialization must consume an ordinary `ValidatedTransaction`.

## Concrete API and representation recommendations

- Add a versioned kernel `SeedDocument` containing the existing `OntologyDocument` and proposed `GraphDocument`. Proposed assertions must carry Proposed, never a caller verdict. Reject unsupported format versions and unknown fields, including nested ontology operation fields: the independent review's newly identified `OperationDefinition.sets` decoder hole is relevant here and should be corrected first.
- Supply operator and validator identity in a trusted execution-context argument when constructing the kernel authority. Do not accept either identity from seed YAML as authority. Keep the operator distinct from the validator and bind proposal attribution to that context; refuse mismatched caller attribution rather than silently accepting or rewriting it.
- Persist the original proposed document plus actual kernel validation attribution in a versioned kernel-owned seed envelope. Reopen recomputes the admission result and validates the attribution against the configured trusted bootstrap context. Deserializing this record confers no capability. Do not accept a caller-supplied validation hash or Accepted field as proof.
- Extend the existing `CommitAuthority` port with seed admission, conceptually `admit_seed(bytes, expected_ontology) -> Result<CanonicalGraph, StoreError>`. A default implementation should fail closed, so existing substitute authorities must explicitly opt into a documented test-only behavior. Prefer extending this existing guarded port to adding a second authority trait that the workspace's authority scan does not know about.
- Move `GraphDocument::into_canonical` and its narrowing/filing logic behind kernel admission. Keep the store graph document as an untrusted DTO with serialization/widening only. A public unchecked narrowing method that accepts an arbitrary closure, bool or hash is not a repair.
- Add `Commit::seed` and read-only methods for `head`, materialized current graph/snapshot, and replay; remove `Commit::store`. Use typed named seed refusals for malformed ontology, graph validation, unsupported format/semantics, missing authority, attribution disagreement, ontology disagreement, and already-seeded state. The ESS Seed command needs its refusal outcome, as the story records.
- Add a dedicated store initialization port. The private store implementation should publish `Seeded` only under `Expected::NoStream`; it must never fall back to unconditional append. The existing raw append remains a substrate/test facility, but replay cannot trust it.

### Initialization atomicity

The pinned eventlog 0.2.1 source already exports `AtomicEventStore`, `AppendGroup`, and `StreamAppend`. Both the SQLite and file providers implement the trait. Use one group for seed object publication plus revision-stream `Seeded`, with NoStream on the revision stream. This prevents a concurrent loser or interrupted initialization from leaving partial seed publication; it also makes the existing ESS already-seeded claim ('Nothing was written') honest.

Account for content-addressed deduplication: a valid seed object may already exist even when the revision stream does not. Reuse only hash-verified matching bytes; do not overwrite them. If a concurrent object insertion causes an object-stream conflict, re-read and distinguish that benign object race from an already initialized revision stream. Never retry by weakening the revision expectation. A fixed initialize command identity or deterministic envelope must not convert a different seed into a successful retry.

If the implementation instead does `put` followed by NoStream append, it protects the lineage but can leave orphaned canonical objects for concurrent losers. That is a narrower guarantee than atomic initialization and the ESS no-write outcome; record or resolve the distinction before dispatch, rather than silently treating the two approaches as equivalent.

## Reuse of validators without bypassing bootstrap rules

Load the complete ontology first. Check root space, root/schema agreement, revision zero, absent parent, schema version zero/no parent, entity map filing and evidence filing before any normalization. The current conversion silently overwrites document.revision in Fold and accepts non-self foreign root parents; bootstrap should reject those rather than discard them.

Build the seed candidate against an empty graph over the validated ontology with retained seed evidence available. Reuse reference, type, cardinality, ontology-constraint and provenance checks over proposed nodes, edges and assertions. Seed evidence introduction and the empty-graph case are explicit bootstrap branches. Do not disable ordinary empty-transaction or evidence rules globally.

Check bootstrap-specific state which NodeDraft does not carry: a node with a lifecycle starts at exactly its declared initial state, and a node without a lifecycle cannot carry a state. Check all caller assertion verdicts before constructing accepted assertions; attach the actual kernel validator only after successful validation. Node/edge properties in GraphDocument are singular values, whereas drafts carry vectors: each stored scalar becomes one property occurrence. Value::List is a single list-valued property, not multiple property occurrences.

Only after successful admission should kernel-owned narrowing produce CanonicalRef values and a CanonicalGraph. Preserve aliases, temporal ranges and evidence unchanged except for explicitly authorized acceptance attribution; do not lose fields by reconstructing everything from the smaller NodeDraft shape.

## Scope additions and contradictions to settle

- `crates/ekr-kernel/src/issue.rs` is not scoped if seed refusal types/codes are placed there; placing the new bootstrap errors in scoped seed.rs avoids that extension.
- `crates/ekr-ontology/src/schema.rs` and ontology tests are needed only if adding `Ontology::to_document`; not necessary for persisted-document loading and full Ontology equality. If added, test round-trip declaration equality and deterministic ordering.
- `crates/ekr/tests/story_contract.rs` / public-surface guards may need updates to enforce removal of the raw accessor and the seed authority crossing. Add those exact paths before editing. New private helpers should use explicit `pub(super)` to avoid the existing scanner's false-public classification.
- Removing the public store narrowing method means its numerous store boundary tests cannot remain direct callers. Move behavioral refusal coverage into kernel tests; preserve provider mechanics under explicit substitute authorities, with fixtures that do not pretend to establish kernel acceptance. Do not add an ekr-kernel dependency to ekr-store merely to keep these tests in place.
- A raw GraphDocument seed previously persisted without a full ontology or attribution cannot be honestly upgraded by inventing either. Preserve its bytes and return an explicit legacy-format/migration-required refusal. This seed wave must not silently reinitialize existing stores; the approved preserve-existing-stores migration work remains necessary.
- The minimal seed contract mentions validator specs/agent roles, but the story explicitly declines full configurable policy. Persist and validate the actual bootstrap actor attribution; do not label a hard-coded validator set as implemented agent policy or claim a populated agent root yet.

## Minimal red-first implementation order

1. Add kernel tests against real SQLite and file stores for the three archived defects: dangling edge endpoint, undeclared node type, and Accepted-with-empty-validators. Assert named refusals and absence of both the calculated seed object and Seeded event. Adapt the archived tests to the current typed references; do not copy their obsolete bare-node CanonicalGraph constructors verbatim. Observe behavioral red before repair.
2. Add valid empty and evidence-bearing controls, deterministic root under fixed input/context, initial lifecycle checks, input filing/space/schema/float checks, unsupported constraints, and no self-validation. Establish the new public kernel bootstrap seam, then shared validation and private narrowing.
3. Add real close/reopen, replay equality, missing-authority, same-schema-id/different-definition, tampered payload and forged-attribution tests. Wire authority admission into production fold_from and hash verification into seed object loading. Do not satisfy these through the store suite's substitute authority.
4. Add repeated initialization and a synchronized two-writer test with distinct seeds, using one separately opened store per thread because the kernel's existing Rc<RefCell> authority is not Send. Assert exactly one winner, one canonical lineage, no replacement and no partial published seed on a failed attempt. Implement atomic initialization with NoStream.
5. Remove Commit::store and old unchecked conversion; migrate read callers and test-only raw corruption handles. Replace the old successful-dangling-conversion test with an actual refusal at kernel admission. Run package checks then the full repository gate, including public-surface and authority guards.

No performance shortcut, cached seed allow-list, test authority or missing-schema reconstruction should substitute for these acceptance paths.
