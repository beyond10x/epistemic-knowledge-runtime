## Wave 2 — the membrane refuses what it claims to

**N = 1.** Every defect is in `crates/ekr-kernel/src/validate/`.

- **Assertion typing.** A `Type` object against a property declared `String`, and a `String` object
  against a relation restricted to node endpoints, are both accepted. Some branches check the
  predicate exists without enforcing its declared semantics. `validate/types.rs:230`.
- **Post-state agreement.** `reference.rs:176` adds created identities and does not remove deleted
  ones; `cardinality.rs` removes them. Two validators, two theories of the resulting state — the
  same class the p1-05 adversary found for ordering, on a different axis.
- **Unsupported operations refuse rather than pass.** A type with a nonexistent parent, a property
  modification nothing declares, an `Invoke` carrying an unsupported precondition. `ontology.rs:9`.
  A deferral is a refusal with a reason, not an acceptance.
- **Two conflicting updates of one property** in a transaction read as a set. Undefined today and
  accepted.
- **The CI job.** `.github/workflows/` holds one workflow and it calls the shared privacy gate only.
  **No checked-in job builds or tests this repository**, so six waves of "gate green" rest on my
  local runs and the pull-request check that gated six merges checked privacy. Add a correctness job
  running `task check` and require it.

**Acceptance**: the probe's seven membrane lines flip from ACCEPTED to a named refusal, and the CI
job runs `task check` on a pull request. The probe is reproducible — the review left its manifest
and `cargo run --offline` reruns it.
