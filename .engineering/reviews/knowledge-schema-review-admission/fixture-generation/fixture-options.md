# ESS 0.52 recursive fixture boundary

The released CLI validates these command declarations and generates both Rust layouts, but conformance fixture admission rejects recursive reachable declarations. `ess-conformance/src/fixtures.rs::Contract::validate` uses `typed_fields::check_type`; that function rejects a repeated named type even through an optional or list wrapper. This is separate from the fixed recursive Rust layout generation.

Probes used a scratch specification containing only the isolated E patch, not F declarations. No repository or ESS source was changed during this investigation; no Cargo or target execution ran.

1. Remove only `ImportInterpretation.document` and `SubmitSchemaProposal.proposal` fixture bindings; keep their Bytes payload fixtures. `ess conform synthesize --component ekr-integrate` successfully writes the suite without the recursive fixture refusal. This is not semantic success: its generated proposal has no observations, sources or evidence. Current proposal admission correctly refuses that input, and setup cannot add citations to the submitted value. An adapter must not replace the literal input.
2. An explicit finite `ess-scenario/3` proposal literal with one cited Evidence UUID plus a typed `schema-proposal-payload: Bytes` fixture compiles successfully: 1 authored scenario, 0 refusals, suite/18. Exact payload and retained support must still be supplied and executed. The proof is `finite-proposal-author.log`; the authored source is `finite-proposal-scenario.yaml`. This route supports truthful authored coverage but does not discharge a synthesized obligation or justify lowering its execution floor.
3. A structured command-input `example:` is not supported: source `command.rs::example_admitted` admits only primitive/enum scalars through newtype/optional layers. There is no supported nested `fixture_inputs` field mapping. A recursive typed fixture or explicit structured witness extension would need an upstream capability change; the frozen release cannot be represented as supporting it.

Keep the unsupported generated obligation visible. Do not coerce the production input type to Json, substitute inputs inside ExecuteCommand, synthesize a supporting citation the caller never supplied, or count authored scenarios as generated execution. CLI success alone is insufficient: conformance author may write an empty suite while reporting refusal, so check both count and refusal diagnostics.
