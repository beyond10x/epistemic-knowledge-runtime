## Contract and inspected sources

The required envelope is `ekr.transaction-document/1`, containing the full `GraphTransaction<Value>`. Retain the original UTF-8 bytes, including whitespace and nonfinite Float syntax; never round-trip through JSON to manufacture the original input. Malformed/empty submissions refuse before Proposed; a well-formed Float may reach Proposed and then receive the named validation refusal. These requirements come from `.engineering/waves/p1-durable-record-decisions.md:63` and the two transaction-document cases in `.engineering/waves/p1-writer-activation-corrected-acceptance.md`.

Reuse explicit version dispatch and strict typed boundaries, not an assumption that this is already a bounded document parser. |
| Unknown transaction fields | `crates/ekr-kernel/src/transaction.rs:62,77,88,108,122,163`: NodeDraft, PropertyMutation, EdgeDraft, EntityMerge, GraphOperation and GraphTransaction currently lack `deny_unknown_fields`. Graph/ontology nested carriers and checked temporal conversions must remain effective. |

| One document | `serde_yaml_ng/src/de.rs:97–146`: direct deserialization loads one document, decodes it, then checks for another and returns MoreThanOneDocument. Taking only the first Deserializer iterator item would remove this protection. The second document is buffered before refusal. |
| Input/event allocation | `src/loader.rs:22–40` reads a Reader to the end into a Vec. `next_document:43` eagerly builds an event Vec and anchor maps before typed visitors execute. `src/libyaml/parser.rs:109` copies normalized scalar bytes into owned storage. No public configurable loader/event/anchor limits are exposed. Never pass an unbounded Reader directly to this API. |
| Aliases | The loader records anchors and alias targets without expanding the document tree. Actual visits jump to target events (`src/de.rs:474`); a shared repetition counter refuses beyond `events.len() * 100`. This is not a byte or output-node bound. Unknown anchors refuse in the loader. |
| Depth | `src/de.rs:112,133,632` starts with a fixed 128 recursion allowance and decrements on particular deserialize operations, including newtypes. This is a library recursion limit, not a configurable 128-level YAML syntax or semantic-value contract. It runs after event buffering. |
| NaN and other floats | `src/de.rs:1066` recognizes `.nan`, `.NaN`, `.NAN` and infinity spellings. `src/value/de.rs` also represents float values without JSON conversion. Retain the bytes and transient Float; canonical admissibility remains the validator's decision. |
| Shape coercion | `src/de.rs:1609` and `:1659` accept an empty plain scalar or Void as an empty sequence/map. Thus `values:` and `properties:` can become empty collections under direct typed decoding. Strict mismatched-nesting refusal requires an explicit shape check; a wrapper seeing only the resulting visit_seq/visit_map cannot recover this distinction. Explicit `[]` and `{}` remain valid when the schema permits them. |
| Typed strings versus YAML Value | `src/de.rs:1471` supplies a scalar's text to a requested String, including plain scalar text that generic Value would resolve as a number/bool. `src/value/de.rs:321` accepts only Value::String for String. Consequently `from_str::<Value>` followed by `from_value::<Transaction>` changes parsing semantics. A shape/budget preflight must not silently replace the typed decode with that conversion. |
| Operation tags / JSON subset | GraphOperation is externally tagged (`transaction.rs:122`). `src/de.rs:1700` expects YAML tags for payload variants, such as `!CreateNode`, and rejects an untagged mapping in that position. Do not promise that an ordinary JSON enum object is accepted merely because JSON lexically fits YAML. Keep the approved “supported subset” qualification; bind the actual operation spelling to fixtures. |
| Merge keys | YAML merge processing is an explicit `Value::apply_merge` operation (`src/value/mod.rs:626`), not a needed transaction feature. Do not invoke it. A unique Record key `<<` remains data; an undeclared semantic field with that name refuses. |

## Proposed implementation boundary

1. Bound bytes before UTF-8 conversion, parser entry, unrestricted copying or read_to_end. For an existing byte slice check length first. For a stream read incrementally with at most `max_input_bytes + 1` retained bytes; do not trust metadata or reserve from an untrusted size hint. Validate UTF-8 without replacement, then retain these exact bytes once. Hash the original bytes, not a normalized parse tree.
2. Apply shared budgets while visiting the representation, before descending into a child or allocating its string/collection entry. Propagate them through every MapAccess, SeqAccess, enum/variant payload and DeserializeSeed, including Serde's intermediate enum-content buffering. Do not first deserialize an unrestricted YAML Value/typed transaction and subsequently count it.
3. A bounded syntax/shape preflight may use the same public YAML deserializer with a custom budgeted visitor, followed by strict typed decoding from the original bytes. Its retained representation must itself obey every budget. Use that shape information to distinguish missing/null values from actual required maps/sequences. Do not use unbounded Value as the preflight or silently adopt Value-to-typed coercions. Alternatively an implementation may combine these checks in the strict decoding adapter, but it must demonstrate that empty-scalar coercion is caught before the underlying typed map/sequence conversion hides it.
4. Every fixed semantic carrier must reject unknown/duplicate fields. Every data map must reject duplicate keys after decoding into its actual key type, before its second value is decoded. This catches both escaped equivalent Record strings and textual aliases of an ID. A generic YAML duplicate check is useful but does not replace the typed check.
5. Permit supported aliases only within the same expanded budgets: each occurrence charges the repeated subtree, strings and nesting, without resetting counters at an alias. Preserve normal operation tags. Do not attempt to detect YAML syntax using regexes over arbitrary scalar data.

The early byte cap bounds the input admitted to the eager loader; its event tape does not expand aliases. The later visitor limits bound recursive semantic expansion and application allocations. This is not an exact allocator-byte guarantee. In particular, a scalar/event may already have been allocated by the loader before a stricter string/node/depth quota is checked. The implementation must state this honestly.

If the intended requirement instead demands a caller-selected event count, raw YAML nesting limit, anchor/alias prohibition or scalar limit checked **before the loader allocates those events/scalars**, the pinned public API cannot supply that guarantee. That is a precise parser-owner capability prerequisite: bounded event production/loading with an early refusal, not an EKR parallel YAML lexer or direct unsafe parser integration. The proposed byte cap plus bounded expansion does not pretend to supply these stronger guarantees.

## Proposed frozen DocumentLimits for document/1

These are conservative policy choices, not measured throughput/heap thresholds. They apply to the submitted wire document and expanded representation, independently of ontology cardinality. Exact maxima are inclusive; exceeding them refuses before Proposed.

| Limit | Proposed default and counting rule |
|---|---|
| Input bytes | 262,144 bytes (256 KiB), including BOM, comments, whitespace and document markers. |
| Documents | Exactly one. A second empty document also refuses. |
| Container depth | 32, root container is depth 1; each nested mapping, sequence or explicit enum payload boundary adds one. An alias uses its expanded position, not a fresh depth. Rust newtype/Box/Option implementation wrappers add no artificial semantic depth. Freeze this accounting in fixtures, rather than copying the library's recursion counter. |
| Expanded nodes | 32,768: each mapping, sequence, enum payload boundary and scalar (including each map key) counts. Each alias occurrence contributes its expanded nodes. Internal repeat passes do not change the profile's semantic count. |
| Entries in one mapping | 4,096, including fields/keys being checked for uniqueness. |
| Elements in one sequence | 4,096 input elements, before set normalization or collection allocation. |
| One decoded string | 65,536 UTF-8 bytes, checked before forwarding a borrowed string to an allocating visitor. Numeric scalar lexemes are covered by the raw input bound; their fixed-size values contribute nodes, not fictitious string lengths. |
| One decoded map key | 4,096 UTF-8 bytes before typed parsing. Empty Record keys are not independently forbidden. |
| Total expanded string bytes | 1,048,576 UTF-8 bytes across materialized strings and keys; charge every alias occurrence. No character-count substitution. |
| Operations | 1 through 256, counted before appending each operation. The minimum is structural; supported/unsupported semantics remain validation decisions. |
| Evidence-manifest elements | At most 1,024 decoded input elements, before any set normalization. This is a resource limit, not a new policy declaring every repeated set element semantically invalid. |

Implement counters with checked arithmetic and named, stable refusals identifying the limit. At an exactly full sequence/map, probing whether another entry exists must not allocate that entry's value: pass a refusing seed if another child is present. The whole-input parser still needs to consume/check document termination and reject additional documents.

Freeze these choices under `ekr.transaction-document/1`; the format version already supplies a profile selector, so no new document format/field is needed for this proposal. Proposal, Validate and authoritative replay must select that same profile. A host upload cap can be stricter at ingress before Proposed, but must not redefine previously retained validity. A future changed profile requires an explicit version/migration decision. An unavailable historical decoder or operational resource refusal must fail explicitly, rather than silently reinterpret history using current host defaults. Preserve versioned fixtures across parser dependency upgrades.

## Required boundary acceptance (unexecuted)

- For each limit, independently construct a valid exact-boundary control and a one-over input, with other limits not masking the intended refusal. Count bytes using multibyte UTF-8 controls; cover short-reading/growing streams without trusting metadata. Instrument decoder/visitor allocation boundaries to establish that over-budget children/strings are refused before application allocation. No benchmark result is claimed here.
- Duplicate envelope `format`, transaction field, operation field, Value envelope field, escaped-equivalent Record key (`a` and `\u0061`), and two supported textual spellings of the same typed property ID must refuse. Distinct Record keys named `format`, `transaction`, `operations`, `value_kind`, `<<`, `true`, Unicode and the empty string must load within limits. Preserve duplicate list elements and outer property order.
- Refuse unknown semantic fields at every reachable nested record, including unsupported operations. Refuse wrong map/sequence nesting and implicit empty scalar in required collection positions. Explicit empty Record/inner List remains representable; empty operations refuses. Optional fields retain their declared null semantics.
- Accept one supported document with optional start/end markers and trailing comments; refuse a second populated or empty document, invalid UTF-8 and missing required content. Preserve supplied CRLF/BOM/comments/whitespace in the retained bytes wherever their syntax is accepted.
- At supported Float positions, retain `.nan`/case variants and infinity bytes through Proposed and restart, then record the named type refusal without manufacturing canonical hashes. A quoted `.nan` in a String remains a String. Exercise actual tagged operation syntax and an explicitly supported JSON-subset control; do not invent a JSON enum encoding.
- A small supported alias succeeds. Repeated aliases exceeding expanded nodes/string bytes/depth refuse before the excessive subtree is built. Recursive and unknown aliases refuse without process failure. Literal `*`, `&` and `<<` inside string/Record data remain ordinary data. Test depth with tagged operations and inner List/Record nesting, not only untyped YAML arrays.
- After proposal, alter unrelated host ingress limits and restart: exact retained bytes, document hash and original document/1 parse/verdict remain stable. All parser refusals leave objects/events and transaction state unchanged; parser-specific library errors must not become fabricated Rejected receipts.

Disposition: reusable strict-field and unique-map patterns exist, but current SeedDocument decoding alone does not fulfill the transaction-document contract. No new persisted format or provider subsystem is required for the proposed byte-capped, expansion-bounded route. Stronger pre-loader quotas require an explicit parser capability; they must not be claimed from post-parse checks.
