# Reviewed Observation support in schema applications

This checkpoint implements design 105.18: an explicit knowledge/3 transition permits exact,
approved Observation support in elected schema applications. Ordinary AddEvidence and historical
profiles keep their previous source restrictions. Application wrappers preserve source identity,
bytes, timestamps and confidence, with extraction attributed to the approving operator.

The support plan uses the initial approval's exact revision. An identical source record admitted
after review cannot change the elected wrapper allocation; a conflicting record refuses before
election and at guarded occurrences. The replay path reconstructs the same plan from authenticated
retained inputs. Validation's private evidence capability neither authorizes publication nor uses
the context-free verdict cache. Publication still requires the exact elected transaction, effective
human review and atomic coordination marker.

## Verification

`verification.txt` retains actual runner summaries and checks. Raw logs and mutation backups remain
outside disposable build output in the private task evidence directory. The native tests execute
both file and SQLite branches; these are not generated ESS conformance results.

- `approved_observation_support_requires_knowledge_three` exercises an Observation-backed schema
  application, exact source bytes and time, zero-confidence direct observation support, repeated
  application, full replay and continued refusal of unsigned Observation additions.
- `application_wrappers_preserve_source_and_attribution` checks the selected fact's support,
  immutable original interpretation, correct wrapper attribution, unrelated later admission of an
  identical source record, and refusal of a conflicting record before retaining an election.
- `application_observation_explanation_survives_source_root_removal` compares exact evidence links
  and full-replay explanations. Separately captured authenticated history and reads remain usable
  after deleting only the test's temporary provider. Missing or altered pinned source objects and
  a caller-modified evidence source refuse. This proves detached-history independence, not a
  product garbage collector or reopening a deleted provider.
- `knowledge_two_history_survives_the_reviewed_third_profile` creates genuine signed knowledge/2
  history through the existing publication path, upgrades to /3, preserves historical bytes,
  decisions and explanations, and requires pending validation to be repeated. These are records
  generated by the current binary, not a frozen archive from a previous binary.

Two one-variable mutation probes failed at the intended seams: planning wrappers at the current
revision instead of the approved revision failed the later-identical-source case, and disabling
Observation explanation failed with `evidence-source-unexplained`. Both mutations were restored
before the final regression run. Initial fixture compile failures are not counted as behavioral red
evidence.
