# Exact additive schema operation planning

This bounded F increment extracts ordinary schema operations from the checked proposal candidate
without allocating replacement identities. Candidate admission uses that same additive boundary.
It does not elect, approve or publish an application.

The retained command output is sanitized only for local worktree/build paths; original logs remain
in the assigned private evidence directory. Status files contain each actual process exit code.
The initial two-case run returned 101 with one failed positive case against an explicit refusing
stub. The implementation passed both cases. The final regression includes a third refusal case:
`cargo test --locked -p ekr-kernel --lib --test schema_proposal_reviews -- --nocapture`
reported 31 library cases and 8 proposal-review cases passed, no failures or ignored cases.
`cargo clippy --locked -p ekr-kernel --lib -- -D warnings` returned zero.

Independent source/log review approved this increment, with no independent execution claimed.
The review names the authority precondition: candidate extraction is not approval or admission.
F persistence, exact signed application validation, guarded publication/recovery, both-provider
application scenarios, demonstrations and the full gate are still outstanding.
