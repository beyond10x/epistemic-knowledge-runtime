# Signed answer verification foundation

Existing ESS ClaimCorrection, AttentionItem and HumanDecision contracts now drive the design section 105.6 correction-list codec and Reviewer::verify_attention. The codec preserves ordered fields and corrections, UUID bytes, optional bounds and epoch-millisecond signed integers. A fixed binary vector, field/order mutations, invalid scalars and equivalent time-zone representations hold that format. No new handwritten DTO or generator artifact is introduced.

Verification retains the original signed observed revision and compares material evidence/options/effects against a fresh current question. Unrelated advancement and presentation-only changes preserve the original signature; changed material or a future reviewed revision requires review again. Subject/scope substitution, changed corrections, statement, predecessor and a forged signature are refused. Operator identity still comes from independently provisioned policy. The caller must use a real kernel projection at atomic publication; this helper alone cannot apply corrections.

Source inspection found two constraints for the next implementation: validate/lifecycle.rs admits withdrawal only for accepted/current claims, excluding disputed claims; and ordinary SupersedeAssertion truncates the old valid interval and requires its replacement start to lie within that interval. A signed-answer path must validate disputed corrections under its reviewed command context without silently weakening old replay or ordinary unsigned transactions. It must retain the earlier assertion and its interval and record the explicit replacement and human evidence.
