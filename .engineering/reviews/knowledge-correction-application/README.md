# Reviewed final corrections for approved schema applications

The correction implementation extends the ordinary application path after its schema and selected
mapping commits. A signed schema approval derives one final atomic correction over all affected
disputes; it never becomes an AttentionAnswer. Exact temporal replacement identities and operations
are frozen once. Explicit Unresolved remains Partial with corrections pending and no correction
transaction. Ordinary unsigned transactions retain their existing lifecycle restrictions.

The generated step records its originating review. Publication independently requires the latest
effective approval and unchanged remaining material. A renewed approval preserves the original
statement and allocations. Explain retains both reviews, the proposal and actual guarded commit,
follows old and replacement assertions, and preserves their source evidence after reopen.

The specification changes precede regenerated runtime contracts. Native tests execute both File
and SQLite. These checks do not establish ESS conformance, full F completion or the full gate.
Upstream ESS issue 416 still blocks generated obligations for finite recursive input fixtures.

## Recovery boundaries exercised

Real ordinary commits reconstruct interrupted prefixes; no test invents a canonical receipt.
Coverage includes an elected correction renewed before Propose, rejection after Validate followed
by approval, an unrelated commit followed by a terminal-stale successor, and a correction commit
missing its final progress receipt. Recovery preserves frozen identities and completed retries
append no events. Copied unsigned correction operations remain rejected.

These reconstructed prefixes test retained-state recovery. They are not an OS-kill experiment or
an exhaustively scheduled concurrent interleaving. The unchanged attention-answer recovery target
continues to exercise its existing process-death boundaries.
