## Objective

From `atlas/ROADMAP.md` O5: the customer-facing product — a person signs up, configures agents,
workflows, data sources and connectors, and sees how the work is being done.

## This repository's contribution

The memory the platform's agents read from and propose to. Observations arrive through Connectors
(`design § 54`); agents are proposers behind a validation membrane (§ 6.7, § 18); people see what the
runtime is unsure about and answer it (amendment 81); every outward write is an approved transaction
(amendment 83).

## Evidence that closes this contribution

An agent session that proposes through `ekr propose` and cannot reach canonical state any other
way; an attention page a person answers; a read-only MCP surface an agent consumes.
