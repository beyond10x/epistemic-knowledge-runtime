## Outcome

Import observations independently of canonical revisions and retain immutable typed interpretations with local schemas, source observation references, blockers and processing receipts. Repeated import returns the original receipt without duplicate records. Unmappable knowledge and rejected interpretations' source bytes remain inspectable after reopen.

## Boundaries

Reuse existing observation idempotency keys and GraphRoot/TransientGraph. Cited bytes are pinned; roots do not own observations. Exact document coordinates and digest envelopes avoid self-referential hashes. Validate local interpretation shape without requiring canonical mapping. No polling, checkpoints, GC, general retention reclamation or canonical observation-evidence admission in this story.

## Acceptance

Named implementation cases: observation_retry_is_idempotent; rejected_interpretation_retains_its_sources; unmapped_knowledge_survives_reopen. Cover native provider atomic failure/restart, content mismatch, immutable versions and inspectable exact bytes. Supply observe import and incubate import/list/show through CLI and typed SDK; viewer read presentation where relevant.

## Scope

Cited by scoper source inspection: crates/ekr-store/src/eventlog.rs object_append and atomic (independent BlobAppendGroup), crates/ekr-observe existing import/idempotency model. Inferred new retention port/child module and record types, crates/ekr-integrate local document validation, crates/ekr-kernel Runtime facade, crates/ekr CLI/session, crates/ekr-sdk transport methods and provider conformance tests. Store mutation remains reachable only through kernel, with architecture guards updated for legitimate ports.

## Shared idempotency implementation

The CLI/SDK boundary requires observation identities without linking runtime crates into the SDK. Move the existing ObservationIdempotencyKey value and its unchanged canonical encoding/UUID derivation into ekr-core, re-export it from ekr-observe, and use that same implementation in the kernel and SDK. This preserves the existing key and identifier contract; it adds no alternate identity algorithm. The existing observation adapter tests must hold the original results unchanged.

## Runtime boundary refinements

Named InterpretationImport, InterpretationRead and RetainedInterpretation projections were added to the existing ESS domain and validated before implementation. They give the CLI/SDK and native retention journal generated contracts rather than handwritten wire models. Exact source bytes remain the version digest; the transient graph is materialized for inspection, never serialized as canonical state. The same specification and generated bytes were synchronized into integration and both active unit trees.

The kernel reuses ekr-integrate's local extraction shape checker through a new incubation-only entry point. This adds a kernel-to-integrate dependency without a cycle; the SDK keeps its transport-only runtime boundary. The original extraction path continues to refuse unsupported observation evidence for canonical publication. Retained observation references are admitted separately during incubation and do not grant canonical evidence authority.

The generated Timestamp projection is RFC 3339 text. The first observation builder incorrectly used decimal milliseconds; runtime ingress and SDK input now use the declared wire format, with format-aware JSON Schema and no-mutation refusal tests. Existing canonical timestamp bytes remain unchanged.

Local review also found that the old preserving migrate command would omit independent streams. It now refuses unsupported stream kinds before destination publication; this delivery does not claim the separate general migration work is complete. Both findings belong to the coordinator acting as implementor; no independent review is claimed.
